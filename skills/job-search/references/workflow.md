# Continue the candidate's campaign

Use for an ongoing search or application session. Read only the task-specific references linked below; this is not a new onboarding checklist or an automatic application pipeline.

## Recover once, then act

Read the designated private profile, current submission mode, chosen tracker and latest relevant events. Follow their saved pointers to the queue, materials, evidence and any employer-target/search-plan records. For a request for different or new jobs, recover the dated exclusion baseline and unfinished company scopes before repeating searches. Read the current workbook before changing it; a generation script or old export is not the user's latest tracker. Keep a compact working brief rather than repeatedly reading unchanged source documents. See [profile](profile.md) for evidence and revision rules.

Resolve the current request to search, selected-job preparation, final-review handoff or outcome recording. Explicit candidate selections take priority over an old queue order. A queue number is a position in a dated snapshot, not a durable job identity. If the request leaves the next action open, surface the smallest useful choice from existing leads or unfinished selected work; do not silently expand into another exhaustive search or applications to unselected jobs.

| Current need | Useful next action |
|---|---|
| New opportunities | Use [search](search.md) in the requested mode. Report each source's actual last successful scope and remaining work; enabled sources and signed-in profiles are not completed scans. |
| Apply to selected jobs | Work in a manageable selected batch. Refresh those exact postings, reconcile prior applications and resolve hard constraints before substantial document work. Use [selected-job applications](submit-applications.md). |
| Repeated document preparation | Compare existing versions first; change only what materially helps the selected role. Use the material reuse rules in [applications](applications.md#reuse-and-version-materials). |
| Missing application answers | Ask one compact, job-labelled set of material questions; reuse established facts and continue independent permitted work. Use [answer bank](answer-bank.md) when repetition justifies it. |
| Candidate reports a send, reply or interview | Record the reported event and reconcile the working tracker and queue using [tracking](tracking.md#working-tracker-and-reconciliation). Do not restart the application. |

Near-term application work can be a better use of a session than expanding a large existing queue, but follow the user's requested scope. Do not impose a fixed batch size, application quota or universal freshness interval.

## Surface the next useful work

When the user asks what to do next or wants a campaign overview, derive a short action queue from the chosen tracker and current records. Each item needs a job/attempt reference, one concrete next action, an owner, any real due date/time zone, the material or evidence pointer and the blocker if one exists. Keep an unknown deadline unknown; urgency is not a reason to invent a date.

Distinguish ready for candidate review, ready for an authorized next step, blocked on a fact/access, waiting on the employer and completed. A saved file is not automatically reviewed, an uploaded file is not submitted, and a due task is not authorized. Prioritize actual deadlines and confirmed interviews, the candidate's selections and high-value unfinished work within their budget. Do not let a dashboard's stage or a model fit score override those choices.

Reuse existing next-action fields or a compact private note rather than introducing another mandatory tracker. State which record is current and which views could not be reconciled. No background mailbox watcher, recurring search or follow-up sender is implied by a planning queue.

## Close with an actionable handoff

Report what changed, prepared versus submitted status, exact material versions, unresolved facts and the next candidate action. For final-review handoffs, follow the saved submission mode and draft-persistence rules in selected-job applications. A pending blocker on one job should not hold up independent selected jobs.

Reconcile the affected records before reporting completion. Preserve historical source-check dates, identify anything still unsynchronised, and leave a compact continuation pointer to the attempt, files and last observed screen when useful. Do not add a reminder, account change, follow-up send or monitoring job without the required request.
