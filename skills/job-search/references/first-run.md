# Personal setup and an evolving candidate context

Use for a new ongoing search or a candidate asking to set up their own job-search assistant. For a single posting, use the supplied facts without forcing onboarding. The [profile](profile.md) remains the source for evidence, private storage and revision rules.

## Start from their background

Read only the current candidate's supplied facts/materials and any private profile they explicitly identify. A résumé, portfolio, LinkedIn profile, work review or transcript can help but is optional. Ask at most three short questions per round, omit answered topics and continue independent useful work. Do not run a long questionnaire or require every field before a first useful search.

A first round can ask:

1. What work, education and projects should we build on, and which tasks/tools can you use independently? They can share a résumé, portfolio or work examples, or describe their background.
2. What kinds of work interest you, and which adjacent duties would you consider? Explain that the bundled large-company list is the default priority and invite additions or exclusions.
3. Where can you work, and what onsite, hybrid, remote and commute limits apply? Establish country/region eligibility for remote work rather than assuming worldwide access.

Use later rounds only for material unknowns: guaranteed pay floor and currency versus variable compensation; employment types, schedule/start/notice; reported work authorization or sponsorship; languages, current credentials, practical tool depth; acceptable experience requirements; travel, sales conditions or role-specific physical/driving tasks. Choose the highest-value questions rather than asking every subtopic together. Never infer citizenship, a licence, a clean driving record, advanced spreadsheet ability, a completed degree, salary expectations or years of specialist experience.

Keep the candidate's constraints individual. No default city, pay floor, experience cap, diploma date, travel acceptance or capability level comes from the package creator. Their permitted experience range is a search preference, not a statement of their own tenure. Ask only when it matters; an absent numeric experience minimum in a posting remains unknown rather than zero.

Show a compact working summary of supported strengths, hard limits, preferences and open questions, invite corrections and proceed once enough is known. This is not an additional approval gate. The default application mode leaves the final Send/Submit to the candidate; make that visible when applications first become relevant.

## Save useful context in this candidate's own place

Use an explicitly identified private workspace outside the installed skill and sharing folder. A local file-capable session may create profile.json from [the blank template](profile.template.json), a compact evidence register, application-answers.json and PROFILE_CONTEXT.md. Store only what is useful to this job search. Do not save passwords, authentication sessions, identity documents, unrelated account data or personal details from another candidate.

Use [the context outline](context.template.md) for the human-readable snapshot. Keep structured profile/evidence records authoritative when available; the snapshot is a portable, dated summary, not an independent source. Include source pointers, confirmed versus unknown facts, the current profile revision, chosen tracker/material paths and the next useful action. Do not create an application history that has not happened.

Resolve bundled resources against the installed job-search skill or attached package, never against the private profile's directory. The template labels the employer seed resource as relative to the skill root; populate employer_seed_list with an actual accessible file/attachment pointer during setup. If that source later becomes inaccessible, retain the private target register and disclose the missing seed rather than claiming it was loaded.

If file persistence is unavailable, maintain the working context in the current chat and provide an updated, copyable PROFILE_CONTEXT.md for the candidate to keep or attach later. Say clearly when information is only in the current conversation. Do not claim that a file was saved or that another chat/account can remember it without an observed supported mechanism.

Host memory is optional and separate from the private profile. Write persistent host memory only when the candidate explicitly asks and an authorized memory feature is available. Retain only relevant preferences/facts, with dated provenance and corrections; do not change their memory settings. A skill file does not itself grant account memory or access to prior chats. In a future chat, recover the candidate's actual saved files/context instead of assuming continuity.

## Refine through real jobs

Use actual posting requirements and application questions to discover material unknowns. Before asking, check the existing profile/answer bank. Label the role and ask only a decision-changing question: for example, distinguish a licence from a driving record, basic formatting from independent lookups, or using an email platform from coding templates. A partially answered bundle leaves the rest unknown.

After the candidate answers, follow [the answer-bank feedback loop](answer-bank.md#learn-from-live-requirements): retain the exact question, options/help text when known, exact reply, source/date, applicable scope, proposed reusable wording, uncertainty and review status. Update the relevant private facts and reconsider affected searches, exclusions, assessments and unsubmitted drafts. Preserve previous versions and submitted history. Proposed training is not completed skill development.

Reuse a compatible current fact for future drafts without asking the same question again. A question about total experience is not one about experience in a particular tool. Country authorization, sponsorship, compensation, start date, notice, travel and attendance can differ by role or change over time; recheck the material fact before relying on it. Sensitive self-identification and legal attestations need the candidate's supplied choice for that context. Context retention is not blanket permission to fill every form or submit.

## End each useful session with a continuation point

Reconcile the profile revision, answer bank, search/vacancy state and chosen tracker only where relevant to the authorized work. Update the dated context snapshot after material changes; do not repeat a full biography in every response. Report what was actually saved and where, what is only in-chat, unanswered conditions, selected draft/application states and the next useful action. Each new person starts separately.
