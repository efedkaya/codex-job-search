# Apply to jobs the candidate selects

Use this workflow when the user asks to apply to identified roles. Read [applications](applications.md) for evidence-based documents and answers; use [tracking](tracking.md) for persistent attempts and confirmed events. The browser or connector performs the application; the offline tracker only records it.

## Scope and authorization

- Resolve the user's links, employers, requisitions or queue numbers to exact postings. Queue ranks can change: record the queue snapshot, employer, title and canonical URL before acting. Do not expand a selected batch, replace a closed role, or apply to other suggested jobs without the user's instruction.
- Distinguish **prepare documents**, **fill/save without submitting**, and **apply/submit**. Read the candidate's saved submission mode before acting. An explicit request such as "apply to jobs 38 and 40" authorizes relevant professional materials and factual form entry for those resolved jobs; it authorizes final submission only when the candidate has not reserved that action and host rules permit. Do not add a blanket second approval step when no such boundary applies. Choosing jobs, requesting a skill update, or asking whether a role is suitable does not alone authorize submission.
- Follow current tool and host requirements for uploads, communications, credentials, legally binding agreements, attestations and action-time confirmation. An application request does not override them. If a specific step needs the user, finish the permitted preparation first and present the exact remaining step and reason.
- Email applications are in scope only when the selected posting explicitly directs applicants to a verified employer/recruiter address and the user asked to apply. Use the selected role's purpose and relevant materials; do not add networking, follow-ups, extra recipients or unrelated employer contact. Follow host messaging authorization rules and identify the invoked skill in the completion report when it authorizes sending.

## Before entering the application

1. Recheck the exact role and employer-controlled application destination. If the posting is closed or unavailable, report that job's status and continue other selected jobs. An access error is not a confirmed closure; use permitted public/official alternatives without bypassing restrictions.
2. Inspect private application history and any visible portal status for the exact requisition. Skip a confirmed submitted application unless the user explicitly requests a new attempt. An unsubmitted resume file is not a prior application. Resolve a possible cross-post before submitting twice.
3. Reuse the current candidate profile, evidence and [material versions](applications.md#reuse-and-version-materials). Tailor only where useful, verify changed facts and render exported files as required by their format. Do not ask for the same known facts again or invent experience to pass screening.
4. Create or resume a distinct private attempt. Keep the posting/form snapshot, destination, authorization source, question wording, answers and evidence, document paths/versions, unresolved issues and observed progress together. Keep private candidate data outside the installed skill and public repository.

Inspect the accessible form for consequential screening questions before substantial drafting. Show a likely conflict with the exact question and supported candidate facts. Some questions appear only later: record that limit, inspect newly revealed steps and do not invent required answers merely to reach the next page. Recheck the employer/ATS destination after an Apply redirect. Reuse current authorization and established exclusions; clarify a genuine candidate decision without adding a universal approval gate.

## Fill accurately and continue through the real form

- Inspect the actual required and optional fields, choices, help text and limits on each step. Opening Apply or uploading a resume is an intermediate state. Recheck parsed names, dates, education, employers and skills after resume autofill.
- Enter supported professional facts and tailor narrative answers to the actual question. A salary floor is not automatically a desired salary; a diploma in progress is not completed education; AI-assisted work is not independent tool proficiency. Respect employer restrictions on application or assessment assistance and disclose a restriction that changes the available help.
- Leave optional unknowns blank when allowed. Ask a compact, job-labelled question for required missing facts or decisions, with the actual question and choices; continue independent work on other selected jobs while waiting. Do not guess sensitive self-identification, an accommodation request, references, salary expectations or personal attestations. Use "prefer not to disclose" only when the candidate supplied that choice or preference.
- Verify the intended file is attached and the correct version is selected, including the displayed filename and any preview or parse result available. Check narrative length and retained text after navigation. Do not copy unrelated account/profile information into an application.
- Use normal supported browser/connector actions. Pause for a user-completed login, MFA, CAPTCHA or required consent when host rules require it. Do not extract sessions, bypass controls, create accounts with unapproved terms, purchase services, or change account-wide visibility, alerts or settings as a side effect.

## When the candidate performs the final step

If the candidate says to always leave applications for their final review or that the last step is theirs, persist that preference in their designated private profile and apply it across email, employer sites, LinkedIn, Glassdoor, Indeed, Job Bank and other routes. It remains in force when later requests say "apply" or a draft receives ordinary positive feedback; do not infer that the candidate changed who performs Send/Submit.

Complete the permitted preparation, uploads and factual fields, then stop before the action that sends the application, communicates interest or makes a required final attestation. Inspect the meaning of Continue, Finish, Easy Apply and similar controls rather than assuming another review screen follows.

- **Email:** verify sender, recipients, subject, full message and completed attachments; leave a saved draft and provide its review link. Do not send a test, application email or follow-up as part of this handoff.
- **Website/board:** use a genuine save-draft control when available and verify persistence. Otherwise retain the live review page as a handoff and explain that it is only filled in the current session; do not claim an unsaved form is a durable draft. Do not click Submit to make it persist.
- **Handoff:** show the prepared materials, any unresolved facts and screenshot proof under the host's browser rules, with the exact remaining action. Mark the attempt prepared/awaiting candidate review, not submitted. Only record a later submission after observing it or receiving the candidate's explicit report.

## When agent submission is authorized: submit once and establish the result

Before the final action, check the employer/requisition, destination, attached documents, completed required answers and any material uncertainty. Keep an exact snapshot of the materials and answers being submitted. If the user requested submission, the candidate's submission mode allows the agent to perform it, and no host-required confirmation or unresolved required choice remains, complete the final action.

If a final step requires a legal agreement, personal certification or other action-time consent, show the exact statement and request the specific user action or confirmation required by the host. Do not turn an ordinary factual field into an unnecessary approval gate.

After submitting, inspect for an employer/ATS confirmation page, application identifier, portal status or connector send receipt. For a UI submission, retain the confirmation screenshot where supported. Do not record success from a click, spinner, disappearance of the form, saved draft or resume upload alone.

If the result is ambiguous, record **submission uncertain** with the last observed state. Check for a confirmation or existing application before retrying. Do not repeatedly click Submit or send another application email to resolve uncertainty. Stop that attempt if certainty cannot be established and continue independent selected jobs.

## Save and report

Keep **prepared**, **partially filled**, **awaiting candidate input**, **ready for required confirmation**, **submitted**, **submission uncertain**, **closed** and **blocked** distinct in the per-attempt notes. Use only the tracker helper's documented event types; record `submitted` only with observed confirmation or the user's explicit report. A blocked recheck does not erase an earlier confirmed submission.

Complete the [working-tracker reconciliation](tracking.md#working-tracker-and-reconciliation) after a handoff or reported outcome. Keep the candidate's existing row and material IDs; do not create a second attempt when they report sending the draft you already prepared.

Report each selected job's employer/title, what was actually completed, exact document version, confirmation evidence or remaining action, and a link to the relevant result or materials. Avoid claiming a whole batch is done when only some applications succeeded. Preserve exact submitted versions rather than overwriting them during later tailoring.
